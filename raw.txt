# Spa.Inc — Admin & Staff Dashboard

## Project Overview

A centralized web-based dashboard for Spa.Inc that allows management to track customers over time, manage remote massage therapists, monitor payments and revenue, identify top-earning staff, and manage daily operational costs and finances. The system serves two user roles: **Admin** (business owners/managers) and **Staff** (massage therapists).

---

## Tech Stack


| Layer | Technology |
|-------|-----------|
| Frontend | Next.js 14+ (App Router), TypeScript, Tailwind CSS |
| UI Components | shadcn/ui |
| Charts & Analytics | Recharts |
| State Management | React Context + Server Components (minimize client state) |
| Backend / API | Next.js API Routes (Route Handlers) |
| Database | PostgreSQL (via Supabase) |
| ORM | Prisma |
| Authentication | Supabase Auth (email + magic link) |
| File Storage | Supabase Storage (receipts, profile photos) |
| Deployment | Vercel |

## Feature Modules

### 1. Client Tracking & History
**Route:** `/dashboard/clients`

**Capabilities:**
- Client directory with search, filter, and sort
- Individual client profile pages showing: visit history timeline, services received, total spend, appointment frequency, preferences/notes
- Client retention analytics: new vs returning clients over time, visit frequency trends, churn indicators
- Add/edit client records

**Key views:**
- Client list (table with pagination)
- Client detail page (`/dashboard/clients/[id]`)
- Client analytics summary cards on main dashboard

---

### 2. Remote Staff Management
**Route:** `/dashboard/staff`

**Capabilities:**
- Staff directory showing all massage therapists (active/inactive)
- Individual staff profiles with: schedule/availability, session counts, assigned clients, satisfaction ratings, location type (remote vs in-spa)
- Real-time availability overview (who is free, who is booked)
- Schedule management per therapist
- Session tracking: completed, cancelled, no-show rates

**Key views:**
- Staff list with status indicators
- Staff detail page (`/dashboard/staff/[id]`)
- Availability calendar/grid view
- Staff schedule editor

---

### 3. Revenue & Payments
**Route:** `/dashboard/payments`

**Capabilities:**
- Log payments against appointments or as standalone entries
- Payment history with filters: date range, client, staff member, payment method, status
- Revenue breakdowns by: service type, time period (daily/weekly/monthly), individual therapist
- Revenue trend charts (line/bar)
- Payment status tracking (pending, completed, refunded)

**Key views:**
- Payments table with filters
- Revenue analytics page (`/dashboard/analytics/revenue`)
- Dashboard summary cards: today's revenue, MTD, YTD

---

### 4. Top Earner Analytics
**Route:** `/dashboard/analytics/performance`

**Capabilities:**
- Staff leaderboard ranked by earnings (configurable time period)
- Individual performance cards: total revenue generated, number of sessions, average revenue per session, client satisfaction score
- Comparison charts across staff members
- Trend analysis: performance over weeks/months

**Key views:**
- Leaderboard table/cards
- Performance comparison bar charts
- Individual staff performance drill-down

---

### 5. Daily Costs & Finances
**Route:** `/dashboard/finances`

**Capabilities:**
- Expense logging with categories (supplies, utilities, rent, payroll, equipment, marketing, other)
- Recurring expense support (auto-populate daily/weekly/monthly)
- Daily, weekly, monthly cost summaries
- Profit & Loss view: revenue minus expenses over a period
- Financial reports: exportable to CSV/PDF
- Budget vs actual tracking (future enhancement)

**Key views:**
- Expense log table with filters
- Add/edit expense form
- P&L summary page (`/dashboard/finances/pnl`)
- Daily cost breakdown chart

## Authentication & Roles

| Role | Access |
|------|--------|
| **Admin** | Full access — all modules, user management, financial reports, settings |
| **Staff** | Limited — own schedule, own clients, own earnings, no expense management or other staff data |

Middleware checks role on every `/dashboard/*` route. Staff users are redirected away from restricted pages.

## Design Guidelines

- **Color palette:** Deep blue primary (`#1B4F72`), accent blue (`#2E86C1`), light blue surfaces (`#D6EAF8`), neutral grays for text
- **Typography:** Inter (headings + body) via `next/font`
- **Layout:** Fixed sidebar (collapsible on mobile) + top header bar with breadcrumbs
- **Cards:** Rounded corners (8px), subtle shadow, white background
- **Tables:** Alternating row shading, sticky headers, pagination
- **Charts:** Consistent color scheme matching brand palette, tooltips on hover
- **Mobile:** Sidebar collapses to hamburger menu, tables become card views on small screens

## API Routes

All under `/app/api/`:

```
GET/POST        /api/clients              — list / create
GET/PUT/DELETE  /api/clients/[id]         — read / update / delete
GET             /api/clients/[id]/history — visit history

GET/POST        /api/staff                — list / create
GET/PUT         /api/staff/[id]           — read / update
GET/PUT         /api/staff/[id]/schedule  — get / update schedule

GET/POST        /api/appointments         — list / create
PUT             /api/appointments/[id]    — update status/details

GET/POST        /api/payments             — list / create
GET             /api/payments/summary     — revenue summaries (query params for period)

GET/POST        /api/expenses             — list / create
PUT/DELETE      /api/expenses/[id]        — update / delete
GET             /api/expenses/summary     — cost summaries

GET             /api/analytics/revenue    — revenue breakdowns
GET             /api/analytics/leaderboard — staff rankings
GET             /api/analytics/pnl        — profit & loss data
```

## Key Conventions

- **Currency:** All monetary values stored as integers (cents) in DB, formatted on display
- **Dates:** Stored as UTC timestamps, displayed in client's local timezone
- **Pagination:** Cursor-based for large tables, page-based for smaller datasets
- **Validation:** Zod schemas shared between client forms and API route handlers
- **Error handling:** Consistent API response format: `{ data, error, message }`
- **Loading states:** Skeleton components from shadcn/ui for all async content
- **Empty states:** Friendly illustrations + CTAs when no data exists

## Notes & Decisions

- We chose **Supabase** over a custom auth/DB setup for faster development and built-in real-time capabilities (useful for live availability updates in future).
- **Prisma** is used as the ORM for type-safe database access and easy migrations, even with Supabase as the host.
- The leaderboard intentionally only shows **earnings data** to Admin users. Staff can only see their own performance.
- Expense management is **Admin-only** — staff should not see operational cost data.
- The P&L report is a calculated view (total revenue - total expenses) and does not require a separate DB table.
